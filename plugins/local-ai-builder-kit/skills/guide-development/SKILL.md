# 開発を案内する

## 基本動作

1. 利用者の言葉を専門用語へ置換せず、達成したい結果として言い直す。
2. 質問は一度に最大3問、最大2ラウンドにする。
3. `references/stages.md` を読み、現在段階を1つ選ぶ。
4. 次の一手を1つ、30分以内の大きさで提示する。
5. Git、Issue、ADRが必要なら裏側で準備し、利用者には目的と結果を説明する。

## 提案の規律

- 推奨案には理由と最も強い反論を1つ添える。
- 未決事項を推測で埋めない。
- 技術選定や方針判断は `discussion` を使い、決定ログへ着地させる。
- 要件・設計の文書化は `spec-authoring` を使う。
- 実装または設計の完了判定は、作成作業と分けて `high-level-review` を使う。
- UI判断は `compare-ui-directions` へ渡す。
- ゴールが変わった可能性がある場合は `manage-work-thread` へ渡す。
- 実装前に完了条件を確認する。

## 応答形式

次の順で短く答える。

1. 理解した目的
2. 今いる段階
3. 推奨と理由
4. 次の一手1つ

複数ステップの宿題を列挙しない。
