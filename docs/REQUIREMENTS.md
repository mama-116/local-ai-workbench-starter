# Local AI Workbench Starter 要件・設計書

## 1. 問題

LocalLLMを使ったチャット、RAG、ツール実行、定期処理、自律動作を作りたい一般ユーザーは、機能の実装順、技術選定、Gitや設計文書の運用を同時に判断できない。機能を一括で組み合わせると、障害箇所を切り分けられず、AIの提案を評価できないまま開発が進む。

既存資産にはGitHub Flow、Spec-First、レビュー、設計テンプレート、RAG/AIチャットの試作がある。一方、そのまま渡すと選択肢と専門用語が多く、初心者向けの導線にならない。

## 2. ゴールと成功基準

### ゴール

Windows 11上でCodexを使う一般ユーザーが、会話を中心に追加課金ゼロのLocalLLMアプリを段階的に構築できるZIP配布環境を作る。

## 3. やらないこと

### 初版ではやらない

- vLLMを最初の推論基盤にしない
- 複数エージェントによる完全自律開発を最初から有効にしない
- 公開クラウドへ会話・RAG資料を同期しない
- Ollama Cloud、Cloudモデル、有料・無料枠付きAPIを初版へ追加しない
- IssueやGitコマンドの習得を利用者へ要求しない
- 画面デザインをモック選択前に固定しない
- 全過去資産をZIPへコピーしない

### 恒久的に避ける

- 個人アーカイブの生ログ、DB、秘密情報を配布物へ入れる
- 承認なしの外部投稿、外部削除、課金
- 出典やライセンスを確認できない第三者資産の再配布

## 4. 代替案

| 案 | 概要 | 判定理由 |
|---|---|---|
| 何もしない | Codexへ毎回自由文で依頼する | 初期費用はないが、手法と安全境界が再現されないため不採用 |
| 文書だけ配る | README、規約、テンプレートをZIP化する | 読まれないと効かず、機械的ガードがないため単独では不採用 |
| 完成アプリだけ配る | 開発手法を隠し、完成済みアプリを渡す | 利用は簡単だが、今後の開発転用という目的を満たさないため不採用 |
| 補助輪ハーネスを配る | 会話Skill、Plugin、テンプレート、検査を組み合わせる | 利用者の認知負荷を抑えつつ手法を再現できるため採用 |

## 5. 採用する設計

### 5.1 配布物の構造

```text
local-ai-workbench-starter/
  README_FIRST.md
  AGENTS.md
  .codex/
    config.toml
  plugins/
    local-ai-builder-kit/
      .codex-plugin/plugin.json
      skills/
  docs/
    REQUIREMENTS.md
    ARCHITECTURE.md
    GITHUB_FLOW.md
    adr/
    templates/
  scripts/
    check-environment.ps1
    setup-codex-plugin.ps1
    build-distribution.ps1
  app/
```

初版PluginはSkillだけを同梱する。`hooks/`、Plugin内 `scripts/`、`assets/`、MCP、Appsは実体が必要になった時点で追加し、空フォルダーを完成扱いしない。アプリのキャラクタープロンプトはルートの `prompts/` へ複製せず、SQLiteの `character_versions` を正本とする。

### 5.2 初心者向け会話導線

1. 自由文から目的を聞き取る。
2. 解決策を決める前に、成功条件とやらないことを固定する。
3. 意見が分かれる場合は発散と収束を分ける。
4. UIは3案を理由とモック付きで比較する。
5. 決定はADRへ、未決は要件書へ残す。
6. 次の作業を1つだけ提示する。
7. Git/Issueは裏で記録し、利用者へは目的と結果を説明する。

### 5.3 機能の段階

| Phase | 成果物 | 単独完了条件 |
|---|---|---|
| 0 | 配布キット | 新規利用者が環境診断と最初の会話を完了できる |
| 1 | チャット基盤 | Ollamaで会話し、ログをSQLiteへ保存できる |
| 2 | 選択と観測 | モデル、キャラクターを切替え、使用率を記録できる |
| 3 | ローカル翻訳 | 外国語を含む回答の原文を残し、回答単位の手動翻訳または会話単位で任意に有効化した自動翻訳を吹き出し内へ非同期表示できる |
| 4 | RAG | ローカル文書を登録し、出典付き回答ができる |
| 5 | Tools/MCP | 読み取り専用ツールを監査ログ付きで実行できる |
| 6 | Scheduler | 定期処理が重複せず、失敗と再実行を記録できる |
| 7A | Agent / Computer Use初回 | 予算・最大手数・許可ツール内で、承認付きメモ帳操作を10回連続成功できる |
| 7B | 承認付きローカル操作 | 許可フォルダーの可逆なファイル整理と登録済みPowerShellレシピを、計画承認・監査・停止付きで20回連続成功できる |
| 8 | Provider拡張 | WSL2のvLLM等へUIを変えず切替えられる |

## 7. リスクと撤退条件

| リスク | 検知 | 対応・撤退 |
|---|---|---|
| 機能過多で原因切り分け不能 | 2フェーズ以上を同時実装している | 直前の単独動作版へ戻す |
| 初心者が文書を読めない | 最初の作業開始に10分以上かかる | READMEを短縮し会話導線へ移す |
| Web検索へ機密情報が出る | 検索語に会話/RAG本文が含まれる | 検索機能を停止し、抽出層を修正する |
| 自律処理が止まらない | 最大手数・時間を超える | 強制停止し、スケジューラを無効化する |
| 画面変化で別アプリへ入力する | 前面プロセスまたはUI要素が直前観測と異なる | 入力せず停止し、実OS Providerを無効化する |
| 画面内の文章が操作目的を変える | 承認計画にない操作、アプリ、入力が追加される | Policyで拒否し、画面本文を除いた自動再計画をしない |
| Controllerが侵害され、自由なOS操作を要求する | Brokerへ未知操作、任意実行ファイル、パス、キー列、座標、上限変更が届く | Brokerが独立拒否し、Computer Useを無効化する。シェルや汎用入力へフォールバックしない |
| 高い権限や別利用者へ入力する | Controllerまたは対象が管理者、高整合性、SYSTEM、別SID、別セッション、secure desktopである | 入力せず拒否し、昇格して再実行しない |
| AIが最適化を理由に破壊的操作を追加する | 承認計画に保存、削除、設定変更、シェル、制御キー、未知アプリが含まれる | 固定PolicyとBrokerの両方で拒否し、利用者へ安全境界を緩める提案を自動表示しない |
| ファイル整理でデータを失う | 上書き、復元不能な削除、復元ジャーナル不整合を検出する | 実行前に拒否し、当該Providerを無効化して復元試験が通るまで再開しない |
| PowerShellが許可範囲を逸脱する | 未登録コマンド、作業ディレクトリ外、昇格、公開ネットワーク、秘密情報候補、子プロセス上限超過を検出する | 実行せず `denied` とし、自由形式コマンドへフォールバックしない |
| PowerShell停止後も子プロセスが残る | 停止・タイムアウト後に今回のprocess treeが残る | 新規レシピ実行を無効化し、対象treeだけを停止できるまで再開しない |
| localhost経由でCloudモデルへ送信される | ローカル実体を持たないモデルが選択可能になる | 無料運営ガードで拒否し、OllamaのCloud機能を無効化する |
| 無料枠終了や上限超過で費用が発生する | アカウント・APIキー・無料枠を必要とするProviderが追加される | 初版へ採用せずローカル代替へ戻す |
| 第三者Skillを再配布できない | ライセンスが不明 | 同梱せずURL参照または独自実装へ切替える |

## 9. 段階分け

最初の30分タスクは、配布キットの骨格、正本文書、3つの補助輪Skillを作り、構文検証することである。

Phase 0終了時点ではアプリ機能は未実装だが、配布環境だけを安全にレビュー・改善できる。
