# Tools/MCP 画面比較

## 今決めること

選択フォルダーの読み取りとローカルMCPの実行状況を、既存チャット画面でどのように許可・表示・監査するかを決める。ツールの書き込み、削除、外部通信、長時間タスクは今回決めない。

## 共通条件

- 利用者が会話ごとに許可したフォルダーだけを対象にする。
- 内蔵のフォルダー検索・テキスト読み取りと、登録済みローカルMCP 1件から始める。
- 許可後の読み取りは自動実行できるが、実行中表示と追記型の監査記録を必須にする。
- シェル実行、書き込み、削除、公開ネットワーク、MCP Tasks、MCP Samplingは初回対象外とする。

## 比較案

| 案 | 利用者が得るもの | 強い反論 | 見直し条件 |
|---|---|---|---|
| A: 右側統合 | 会話画面を離れず、現在の許可範囲と直近実行を確認できる | 監査履歴が増えると右側だけでは狭い | 1会話あたりのツール実行が20件を超える |
| B: 実行トレイ | どの回答が何を読んだか、時系列で追いやすい | 入力欄付近が狭くなり、日常会話を圧迫する | トレイを閉じたまま使う割合が高い |
| C: 専用管理 | 複数サーバー、許可フォルダー、失敗履歴を一覧管理しやすい | 初回の2種類の読取ツールには過剰 | MCPサーバーが3件以上または監査が100件以上になる |

## 推奨

A案を初回に採用し、回答吹き出しには「資料を何件読んだか」だけを表示する。監査件数が増えた後、Aを維持したままCの専用管理画面を追加する。Bは回答単位の調査が日常的に必要になった場合の代替とする。

## 選択状態

`決定 | 初回はA | 監査履歴が十分に増えた後にCを追加 | ADR-0014を正本とする`

初回のA案では、右側 `CONTROL DESK` に現在の許可フォルダー、利用可能なツール、直近の実行状態、監査記録を開く操作を表示する。回答吹き出しには読取件数だけを表示し、詳細ログを常時展開しない。

C案はA案を置き換えず、監査履歴が100件以上になるか、利用者が右側だけでは追いにくいと判断した時点で追加する。専用画面では会話、ツール、結果、失敗を絞り込めるようにする。
