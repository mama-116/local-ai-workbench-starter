# Computer Use 承認・停止UI比較

## 今決めること

固定メモ帳計画を実行する前に、利用者が対象、入力全文、操作数、隔離先、安全境界を確認して承認し、実行中は即座に停止できる画面構造を選ぶ。保存、削除、設定変更、任意アプリ、Host入力の自動有効化は今回決めない。

## 共通条件

- 同じ計画を表示する: 選定済みの隔離Windows VM内のメモ帳、3操作、最大60秒、入力文「安全確認 2026-07-18」、保存なし。現在は隔離方式が未決のため実行できない将来状態のモックとする。
- `標準権限`、`同一ユーザー/セッション`、`ネットワークなし`、`保存なし` の検査結果を表示する。
- 承認は計画ハッシュと30秒期限へ束縛し、変更時に失効する。
- 実行中は `Ctrl+Alt+F12` と画面上の停止操作を常時示す。停止は承認より目立つ位置・大きさにする。
- 拒否、期限切れ、検査失敗ではOS入力を送らない。危険な境界を解除する「続行」操作は置かない。

## 比較

| 案 | 中心となる操作 | 向いている人 | 採用理由 | 強い反論 |
|---|---|---|---|---|
| A: 右側Safety Gate | 会話を見ながら右側で計画を確認し承認する | 日常会話と安全状態を同時に見たい人 | 既存の `CONTROL DESK` パターンを再利用でき、実行中も停止と隔離状態が常時見える | 270px幅では長い入力文や検査理由を比較しにくく、見落としが起きうる |
| B: 集中レビュー | 会話を一時的に覆う1画面で全項目を確認する | 実行頻度が低く、誤承認を最小化したい人 | 対象、入力、禁止事項、隔離状態を同じ視線内で確認でき、最も慎重 | 毎回会話が中断され、慣れると内容を読まず承認する「承認疲れ」が起きやすい |
| C: 実行バー | 画面下のバーを展開し、2秒長押しで承認する | 短い固定操作を頻繁に使う人 | 画面を占有せず、実行中の停止を入力欄近くへ固定できる | 詳細を閉じたまま承認しやすく、今回のような初期・高リスク機能には情報階層が弱い |

## 推奨

初版は **B: 集中レビュー** を推奨する。今回の目的は操作回数を減らすことより、AIの誤判断・権限境界・隔離先を実行前に確実に見分けることであり、低頻度のメモ帳試験なら中断コストを許容できる。実行開始後はBを閉じ、Aと同じ右側の小さな実行中カードへ切り替えて、大きな停止ボタンだけを常時残す。

最も強い反論は、画面を覆う承認が形式化し、かえって読まれなくなることである。20回の受入で、確認時間が2秒未満の承認が3回以上、または利用者が内容を読み飛ばしたと自己申告した場合はAへ見直す。Cは、Host試験10回成功後も同一固定プロファイルを週5回以上使う場合だけ再検討する。
