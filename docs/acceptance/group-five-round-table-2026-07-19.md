# 5人ラウンドテーブル 実Ollama画面受入結果

実施日: 2026-07-19

判定: 合格（5人生成・保存・名前付き別吹き出し）。性能計測は要修正。

## 対象と完了条件

専用データ領域へテスト用キャラクターと会話設定だけをApplication Serviceで準備し、メッセージとTurnBatchはFlet画面の通常送信経路から生成した。個人会話データと既存アプリは操作していない。

- データ: `tmp/group-five-acceptance-20260719/local_llm_chat.sqlite3`
- Ollama: loopback `http://127.0.0.1:11434`
- モデル: `qwen3.5:9b`
- モード: `round_table`
- キャスト順: アオイ、ベニ、チャイ、ダイダイ、エン
- 入力: 「5人全員が、今日の遠足に持っていきたい物を一つずつ、短い一文で順番に話してください。」

完了条件は、1回の通常送信からキャスト5人が登録順に1回ずつ発言し、名前付きの独立した吹き出しとして表示され、SQLiteの1件のTurnBatchと5件のsegmentが同じ順序・安定キャラクターIDで保存されることとした。

## 結果

| 確認項目 | 結果 |
|---|---|
| 画面の設定表示 | 合格。「ラウンドテーブル・5人」を表示 |
| モデル呼出し | 合格。通常送信1回から応答を完了 |
| 名前付き別吹き出し | 合格。アオイ、ベニ、チャイ、ダイダイ、エンを別々に表示 |
| 発言順 | 合格。キャスト位置0〜4と画面順が一致 |
| TurnBatch | 合格。1件、`completed / not_needed / group-turn-v2`、エラーなし |
| segment | 合格。5件すべて `speaker_kind=character`、未解決話者なし、安定ID一致 |
| 互換AIメッセージ | 合格。5発言を表示名付きで連結し `completed` 保存 |
| 性能表示 | 不合格。Runは `completed` だが応答時間・生成時間がNULLで、画面は「未取得」を表示 |

生成内容は次の順序だった。

1. アオイ: 静かな本
2. ベニ: みんなで楽しめるお菓子
3. チャイ: 必要な薬品
4. ダイダイ: 水分補給のお茶
5. エン: 面白い話

## 判定理由と残る懸念

5人会話の主要目的である「1回生成、5人の安定ID、登録順、名前付き別吹き出し、原子的TurnBatch保存」は実画面とSQLiteの両方で一致したため、機能受入は合格とする。

性能値が欠ける問題は会話内容や保存を壊さないが、単独会話とグループ会話を同じCONTROL DESKで比較できない。`ChatCoordinator` のグループ経路がRun確定時にOllamaのdurationと画面応答時間を保存していない可能性が高い。原因は未診断なので、この受入記録では修正済みとしない。

受入専用Fletウィンドウだけを終了した。専用SQLiteは再現証拠として残している。
