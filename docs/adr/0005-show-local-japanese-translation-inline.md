# ADR-0005: ローカル日本語訳を原文と同じ吹き出しへ併記する

- Status: Accepted
- Date: 2026-07-16
- Decision owner: 利用者

自動翻訳の既定動作は [ADR-0021](0021-make-automatic-translation-opt-in-per-conversation.md) により置き換えられた。原文保持、ローカル限定、吹き出し内併記、再翻訳の決定は引き続き有効とする。

## Context

利用者は英語を読めないが、会話の流れで英語、中国語など日本語以外を扱う可能性がある。AI回答へ外国語や外国語の単語が混ざった場合も会話を止めずに理解できる必要がある。一方、翻訳で原文を上書きすると、誤訳の確認、再翻訳、会話の再現ができなくなる。クラウド翻訳APIは費用経路と外部送信を生むため、`strict_free` とローカル保存の条件に合わない。

## Decision

次回実装では、AI回答に実質的な日本語以外の文章または単語が含まれる場合、ローカルモデルで日本語訳を作り、元の吹き出し内へ併記する。

- 原文を正本として変更せず保存する。
- 日本語訳は原文メッセージUUIDへ関連付けた派生データとして別に保存する。
- 初期表示は「原文、日本語訳、原文を隠す、訳し直す」とする。
- 翻訳対象には外国語だけの文章と、日本語へ英単語等が混ざる文章の両方を含める。
- 会話履歴としてLLMへ渡す内容は原文とし、表示用翻訳を混ぜない。
- 翻訳は原文の逐次表示完了後、上限付き `asyncio.Queue` で実行し、チャット応答を待たせない。
- 同じ原文、対象言語、翻訳Provider、モデルの組合せは再利用する。
- 翻訳失敗時も原文は表示し、吹き出し内から再実行できるようにする。
- 初期の翻訳ProviderはローカルOllamaとし、既存の無料運営ガードを必ず通す。
- Google翻訳、DeepL等の外部API、APIキー、無料枠、従量課金サービスは採用しない。

## Alternatives

- 必要時だけ「日本語に訳す」を押す: 不要な処理を減らせるが、読めない文章が出るたびに操作が必要なため不採用。
- 右側に翻訳専用欄を設ける: 原文比較には向くが、管理欄と会話欄が狭くなるため不採用。
- 翻訳文で原文を置き換える: 画面は簡単になるが、誤訳確認と再現性を失うため不採用。
- クラウド翻訳APIを使う: 品質を選びやすいが、外部送信と費用経路を生むため不採用。

## Consequences

- 外国語を読めなくても会話を継続でき、原文との比較もできる。
- 翻訳結果用のテーブル、状態、キューワーカー、再翻訳操作が必要になる。
- 翻訳分のローカル推論時間と電力を使うが、チャット本文の表示完了は待たせない。
- 翻訳モデルがGPUから外れている場合は訳の表示だけ遅れる可能性がある。
- 言語判定の誤りに備え、手動翻訳と再翻訳を残す必要がある。

## Review condition

自動翻訳の誤検出が日常会話を妨げる場合は、自動表示を既定のまま維持するかを見直し、会話単位の自動・手動切替を追加する。外部翻訳を検討する場合は、本ADRを変更せず、費用・外部送信・承認境界を別ADRで定義する。
