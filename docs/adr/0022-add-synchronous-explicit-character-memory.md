# ADR-0022: 発言選択による明示記憶を同期保存する

- Status: Accepted
- Date: 2026-07-23
- Decision owner: 利用者

## Context

自動抽出される型付き正史記憶だけでは、利用者が「この情報を現在のキャラクターに確実に覚えさせたい」という意図を表せない。一般メモや既存分類に収まらない情報を型付き正史へ押し込むと、事実の意味と置換規則が曖昧になる。一方、自然言語の「覚えて」を自動判定すると、引用、否定、第三者発言を誤保存する危険がある。

保存内容には機微情報が含まれ得る。現在の会話本文と同様、保存先SQLiteは暗号化されていないため、保存範囲と再利用先を操作前に利用者へ示す必要がある。

## Decision

- 単独会話の完了済み利用者発言へ「このキャラクターに覚えさせる」を表示する。
- 発言全文を編集可能な確認欄へ入れ、1〜200文字を同期的にSQLiteへ保存する。201文字以上は切り捨てず、編集を求める。
- 型付き正史記憶とは別に、出典、分岐、会話、安定キャラクターIDを持つ追記型台帳を設ける。Undoも別の追記判断として保存する。
- ダイアログ単位の `request_id` で二重操作を冪等化する。ダイアログを再度開く操作は新しい保存要求とする。
- 保存transaction内で現在会話、active分岐、出典利用者発言、表示経路、現在キャラクター、単独会話状態を再検査する。
- 一般メモと機微情報をローカル保存できる。確認画面に、SQLiteが暗号化されていないことと、再利用時にローカルOllamaへ渡されることを表示する。本文を通常ログやTelemetryへ出さない。
- 単独チャット文脈では、安全制約、明示記憶、その他の自動記憶の順に統合し、既存の32件・16,000文字上限を共有する。同じ出典・同じ値は重複させない。
- 自然言語による保存要求の検出、グループ会話、キャラクター間共有、期限、暗号化、自動バックフィルは初版に含めない。

## Alternatives

- 発言をそのままワンクリック保存する: 操作は短いが、機微情報と保存範囲を確認できず、長文を意図せず残す危険があるため採用しない。
- 自然言語の「覚えて」を自動検出する: 会話的だが、誤検出を保存要求とみなすことになるため初版では採用しない。
- 型付き正史記憶へ新しい種別として保存する: 台帳を増やさずに済むが、自由記述を既存の置換・承認規則へ混ぜると意味が壊れるため採用しない。
- 非同期キューへ投入する: 応答待ちは減るが、利用者が明示した保存の成否が曖昧になるため採用しない。

## Consequences

- SQLite commit成功を保存成功の境界として利用者へ明確に返せる。
- 同じキャラクターの版変更後も記憶を利用でき、別キャラクターや別会話へ漏れない。
- 暗号化されていない保存領域へ機微情報を置けるため、端末やDBファイルへのアクセスを得た第三者には読まれ得る。UI警告と外部送信禁止はこの保存時暗号化の代替ではない。
- 自動記憶と明示記憶の2台帳を投影時に統合するため、重複排除と共有上限の試験が必要になる。

## Review condition

端末共有やDB持ち出しが現実的な利用形態になった場合、または利用者から記憶単位の閲覧保護・期限・削除要求が継続して出た場合は、保存時暗号化とライフサイクルを別ADRで検討する。グループ会話へ明示記憶を渡す要件が生じた場合は、キャラクター別秘密を同一LLM要求へ混在させない分離生成の契約から見直す。
