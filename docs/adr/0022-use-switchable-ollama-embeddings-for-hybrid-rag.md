# ADR-0022: 切替可能なOllama埋め込みでRAGをハイブリッド検索にする

- Status: Accepted
- Date: 2026-07-24
- Decision owner: 利用者

## Context

初期RAGの語句一致は引用位置を安定して示せる一方、日本語の言い換えや表記揺れでは資料を取得できない。埋め込みモデルはこのPCとDGX Sparkの両方にあり、処理時間より検索品質と再現性を優先したい。ただし、モデルや接続先を切り替えたベクトルを混在させると検索結果を再現できず、LAN障害でチャット全体が停止する危険がある。

## Decision

- 語句検索とcosine意味検索を残し、順位はRRF（`k=60`）で統合する。
- 埋め込み用途はアプリ全体で1つ設定し、「用途別モデル設定」から登録済みOllama接続先とembedding capabilityを持つモデルを選ぶ。
- 会話生成モデルは従来どおり会話ごとの設定とする。記憶抽出モデルは後続の
  記憶定着化判断により、Embeddingとは別のアプリ全体用途設定として分離する。
- プロファイルは接続ID、endpoint fingerprint、モデル名、モデルdigest、ベクトル次元で識別する。
- 新プロファイルは別索引としてバックグラウンド構築し、完成後に原子的に有効化する。失敗時は旧索引、旧索引もなければ語句検索を使う。
- モデル保存時に30件の日本語言い換えと20件の無関係質問で校正し、Recall@5 0.90、MRR@5 0.80、無関係質問の無結果率0.85を満たす類似度閾値がないモデルは有効化しない。
- chunk UUID、原文、引用offsetは変更せず、ベクトルだけを再生成可能な派生データとしてSQLiteへ保存する。
- ループバックまたは確認済みプライベートLANの無料Ollamaだけを許可し、実行ごとにCloud無効化とローカルモデル実体を再検査する。ADR-0010の「SQLite以外へ送信しない」は、ADR-0006で許可された確認済みLAN内Ollamaへの推論入力に限って更新する。公開ネットワークと外部APIへの送信は禁止のままとする。

## Alternatives

- 語句検索だけを改善する: 軽量だが、日本語の概念的な言い換えを安定して扱えないため不採用。
- 接続先ごとに現在の索引を上書きする: 保存量は減るが、切替失敗時の復旧と再利用ができないため不採用。
- 会話ごとに埋め込みモデルを持つ: 自由度は高いが、共有資料の索引が増え状態説明も難しくなるため不採用。
- Vector DBを追加する: 大規模検索には有効だが、現時点の件数ではSQLite線形走査で検証できるため後続とする。

## Consequences

- LocalとDGXを切り替えても、モデル由来の索引を混在させず、完成済み索引を再利用できる。
- 初回設定とモデル変更時には品質評価と全chunkの埋め込み時間が必要になる。
- DGX選択時はRAG本文と検索文が確認済みLAN端末へ送られることをUIで明示する。
- 意味検索が故障しても、文書登録、語句検索、引用表示、通常チャットを継続できる。

## Review condition

chunk数が数千件を超えて線形cosine検索が体感を損なう場合はVector DBを比較する。会話や資料ごとに異なる埋め込みが必要になった場合は、索引共有と保存容量を測定して設定単位を見直す。
