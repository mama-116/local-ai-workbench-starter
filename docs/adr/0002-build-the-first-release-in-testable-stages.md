# ADR-0002: 初版を検証可能な段階に分ける

- Status: Accepted
- Date: 2026-07-16
- Decision owner: 利用者

## Context

目標には逐次会話、保存、キャラクター、書き直し、RAG、検索、キャッシュ、非同期処理が含まれる。これらを同時に実装すると、画面停止、通信、保存、検索のどこが原因か切り分けにくくなる。一方、将来の拡張を無視した使い捨て試作では、履歴分岐やProvider追加時に作り直しが必要になる。

## Decision

初版は、1人のキャラクターとの逐次会話、SQLite保存、モデル・キャラクター切替、元を残す書き直しまでとし、契約、Ollama縦切り、選択、分岐、配布の順に単独検証できる段階で実装する。

## Alternatives

- 何もしない: キャラクターと履歴分岐を一体管理する目的を検証できないため却下。
- 全機能を同時に実装する: 障害箇所と利用価値を段階ごとに確認できないため却下。
- 単一ファイルの使い捨て試作を先に作る: 最短で画面は出るが、保存形式と会話分岐を作り直す可能性が高いため却下。

## Consequences

- 各段階で動く状態を保ち、RAGや検索を追加しなくても初版を利用できる。
- 初期から責務境界とテスト用Fakeを用意する分、最初の会話表示までのファイル数は増える。
- RAG、Web検索、応答キャッシュ、複数キャラクター会話の実装は後続判断になる。

## Review condition

最初の縦切り実装が1営業日以内に起動できない場合、抽象化の数と段階の切り方を見直す。単独会話の受入基準が安定した後、複数キャラクター会話を次の独立成果物として検討する。
