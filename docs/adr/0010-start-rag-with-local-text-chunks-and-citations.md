# ADR-0010: RAGはローカル文書の軽量検索と出典から始める

- Status: Accepted
- Date: 2026-07-16
- Decision owner: 利用者

## Context

RAGの初回実装では、文書登録、分割、検索、回答への注入、出典表示を段階的に検証する必要がある。最初から埋め込みモデルとVector DBを追加すると、配布容量、モデル選定、再構築、検索品質の故障箇所が同時に増える。一方、出典のない本文検索だけでは、利用者が回答根拠を確認できない。

## Decision

- 初回はUTF-8の `.txt` と `.md` だけを受け付け、1ファイル5MiBまでとする。
- 文書本文は `PRIVATE` とし、SQLite以外へ送信しない。
- UIやファイルパスではなく、検証済みファイル名とbytesをApplication Serviceへ渡す。保存先は既存の固定ローカルDBとする。
- 原文を変更せず `documents` へ保存し、検索用の `chunks` は再生成可能な派生データとする。
- チャンクは最大800文字、120文字の重なりで開始する。
- 初回検索は追加依存のないローカル文字列検索とし、結果には文書名、文書UUID、チャンクUUID、原文内の開始・終了位置を必ず付ける。
- 空文書、非UTF-8、非対応拡張子、上限超過、パスを含むファイル名は保存前に拒否する。
- 同一内容の再登録は内容ハッシュで再利用し、重複保存しない。
- 検索結果がない場合は空結果を返し、出典を捏造しない。
- RAG画面はA案の右管理欄、B案の専用ライブラリ、C案の入力欄添付を比較し、C案を採用する。
- 入力欄の添付ボタンから会話単位で資料を選び、選択中の資料名を入力欄上へ表示する。
- 回答に渡したチャンクはrunへ関連付け、AI回答の下へ文書名と原文位置を表示する。

## Alternatives

- 最初からローカル埋め込みとVector DBを使う: 意味検索には強いが、配布量と障害箇所が増えるため後続とする。
- Ollamaへ文書全文を毎回渡す: 実装は短いが、文脈上限と応答時間を圧迫し、出典範囲も曖昧になるため不採用。
- OS検索や外部検索へ委譲する: 文書境界と外部送信を制御しにくいため不採用。

## Consequences

- 埋め込みモデルなしで文書登録、再構築、出典の契約を検証できる。
- 言い換えや概念検索には弱い。
- 後から埋め込み検索へ置き換えても、文書UUIDと出典形式を維持できる。
- 文書が増えると入力欄から全体を管理しにくいため、10件を超えた場合は専用ライブラリを再検討する。

## Review condition

同じ意味の別表現を検索できず日常利用を妨げる場合、ローカル埋め込みモデルとSQLite内ベクトルまたは軽量Vector DBを比較する。検索対象が数千チャンクを超え、線形検索が体感を損なう場合も検索方式を見直す。
