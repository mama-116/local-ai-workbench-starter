# ADR-0009: 初回は直近の観測結果を右側管理欄へ表示する

- Status: Accepted
- Date: 2026-07-16
- Decision owner: 利用者

## Context

観測結果には、会話中に直近の性能を確認する用途と、蓄積した複数端末・モデルを比較する用途がある。最初からグラフと履歴表を作ると、まだ少ない記録に対して実装量が大きくなる。一方、回答吹き出しごとに数値を加えると、日常会話の読みやすさを損なう。

## Decision

- 初回はA案を採用し、既存3カラム画面の右側 `CONTROL DESK` に「直近の性能」を表示する。
- 表示項目は、接続先、モデル、応答時間、生成速度、CPU、RAM、GPU、VRAMとする。
- 応答時間と生成速度は、最後に完了したAI回答のrunを対象にする。
- 生成速度はOllamaの出力トークン数と生成時間からトークン毎秒で表示する。
- CPU・RAM・GPU・VRAMには取得元端末を明記する。
- 値を取得できない場合は0と表示せず、「未取得」と理由を短く表示する。
- 観測中または観測失敗でも、会話入力と生成を停止しない。
- 初期状態は常時見える小さなカードとし、詳細値は折りたためるようにする。
- AI回答の吹き出しへ性能値を常時表示するB案は採用しない。
- 観測履歴が蓄積し、複数端末・モデルの比較需要が確認できた後、C案の専用性能比較画面を追加する。

## Initial mock

```text
┌──────────────┐
│ CONTROL DESK │
│ 無料運営:保護中│
│              │
│ 直近の性能    │
│ DGX Spark    │
│ gemma4:31b   │
│ 応答  8.4秒   │
│ 生成 20.4t/s │
│ CPU   未取得  │
│ RAM   未取得  │
│ GPU   未取得  │
│ VRAM  未取得  │
│ [詳細を隠す]  │
└──────────────┘
```

## Alternatives

- B案、回答吹き出し内表示: 回答との対応は明確だが、会話本文が読みにくくなるため不採用。
- C案、専用性能比較画面: 履歴比較には最適だが、記録が少ない初回には過剰なため後続採用。
- 数値を表示せずログだけ保存する: 実装は小さいが、利用者が端末・モデルを選ぶ判断に使えないため不採用。

## Consequences

- 会話画面を離れずに直近の体感と数値を照合できる。
- 右側管理欄の縦幅が増えるため、低い画面では折りたたみが必要になる。
- 初回は履歴の一覧、グラフ、期間比較を提供しない。
- C案追加時も同じ観測データを再利用できる。

## Review condition

右側管理欄が日常操作を圧迫する場合は、初期状態を折りたたみに変更する。複数接続先・複数モデルの実行履歴が蓄積し、直近値だけでは選択判断が難しくなった場合にC案を設計する。
