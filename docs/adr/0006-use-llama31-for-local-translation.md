# ADR-0006: ローカル翻訳専用モデルにLlama 3.1を使う

- Status: Accepted
- Date: 2026-07-16
- Decision owner: 利用者

## Context

会話モデル `qwen2.5:7b` で中国語を日本語へ翻訳したところ、`怎么样`、`焦糖`、`碎片`等が訳文へ残った。温度を0にし、翻訳指示を複数方式で強化しても改善しなかった。同じ原文をローカルの `llama3.1:latest` と `gemma2:9b` で比較すると、どちらも外国語を残さず日本語へ変換できた。

## Decision

翻訳には `llama3.1:latest` を使い、会話モデルと用途を分ける。会話モデルの決定はADR-0007で更新する。

- `TranslationService` の既定翻訳モデルを `llama3.1:latest` に固定する。
- 翻訳キャッシュと保存記録には翻訳専用モデル名を含め、Qwenの既存訳と混同しない。
- 翻訳指示では原文をデータとして囲み、全文翻訳、校正、中国語の語句・文法・簡体字・繁体字を残さないことを明示する。
- 翻訳モデルが存在しない、ローカル実体を確認できない、Cloudが無効でない場合は無料運営ガードで失敗させる。品質の低いモデルへ暗黙に戻さない。
- UIには実際に使用した翻訳モデル名を表示する。

## Alternatives

- `qwen2.5:7b` を会話と翻訳で共用する: 追加VRAMを使わず高速だが、中国語が訳文へ残るため不採用。
- `gemma2:9b` を使う: 日本語は自然だが、Llamaより約0.5GiB大きく、実測生成速度も低かったため次点とする。
- 外部翻訳APIを使う: 外部送信と費用経路を生むため不採用。

## Consequences

- 会話モデル約4.4GiB、翻訳モデル約4.6GiBに実行領域を加えたVRAMを使用する。16GiB環境では同時利用可能な範囲である。
- 初回翻訳ではLlamaの読込に実測約38秒かかるが、読込後は約75トークン/秒で生成できた。
- 外国語の残存は大幅に減るが、8Bモデルのため語義選択等の誤訳を完全には防げない。「訳し直す」と原文表示を維持する。
- 将来、より軽量で高品質なローカル翻訳専用モデルが検証できた場合は差し替えられる。

## Review condition

本人試用で意味上の誤訳が継続的に会話理解を妨げる場合、完全無料・ローカル実行・ライセンス確認を満たす翻訳専用モデルを比較し、本ADRの既定モデルを見直す。
