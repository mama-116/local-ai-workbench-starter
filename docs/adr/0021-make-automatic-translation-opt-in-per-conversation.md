# ADR-0021: 自動翻訳を会話単位の任意設定にする

- Status: Accepted
- Date: 2026-07-20
- Decision owner: 利用者
- Supersedes: ADR-0005の「外国語検出後に常に自動翻訳する」部分

## Context

ADR-0005は外国語を読めない場合にも会話を止めないため自動翻訳を採用し、誤検出が日常会話を妨げた場合は会話単位の自動・手動切替へ見直す条件を定めた。実利用で、翻訳が不要な会話でもローカル推論が自動実行されるため、利用者から翻訳を任意にしたいという要求が出た。この見直しは原文保持、ローカル限定、吹き出し内表示の決定を変更しない。

## Decision

- 既存会話と新規会話の自動翻訳は既定でOFFとする。
- 会話単位の設定を明示的にONにした場合だけ、AI回答の保存完了後に外国語判定と翻訳Queueへの投入を行う。
- OFFでも完了済みAI回答ごとの「日本語訳」操作を常に利用できる。
- 設定変更は将来の回答だけへ適用し、保存済み原文、翻訳試行、再利用キャッシュを変更・削除しない。
- 単独会話とグループ会話は同じ設定を参照する。
- 状態値とデータ境界は `docs/ARCHITECTURE.md` を正本とする。

## Alternatives

- 何もしない: 読めない外国語を自動で補えるが、不要な推論を止められず、利用者の明示要求を満たさないため不採用。
- アプリ全体のON/OFFだけを持つ: 実装は小さいが、翻訳が必要な会話と不要な会話を同時に扱えないため不採用。
- 回答単位の手動翻訳だけに固定する: 動作が最も明確だが、外国語中心の会話では毎回答の操作が必要になるため、自動翻訳を会話単位の選択肢として残す。

## Consequences

- 不要な翻訳によるローカルモデルの待ち時間と電力消費を抑えられる。
- 外国語中心の会話では利用者が1回設定をONにする必要がある。
- 設定を切り替えても過去データを書き換えないため、ロールバックは設定を戻すだけで完了する。

## Review condition

新規会話の過半数で毎回自動翻訳をONにしている状態が30会話以上続いた場合、作成時の選択またはアプリ全体の既定値を追加するか見直す。外部翻訳Providerは本ADRの範囲外とし、検討時は費用・外部送信・承認境界を別ADRで定義する。
