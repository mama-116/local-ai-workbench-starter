# ADR-0027: 共通Reducerとキャラクター別Styleで言動を同期する

## Status

Accepted

## Context

Issue #50で世界線単位のProfile・関係台帳を実装したが、実利用ではLAN会話モデル名をloopback抽出へ流用していたため関係イベントが生成されず、59件のユーザー発言に対して0件だった。候補抽出も応答後であり、現在発言への言動と後から確定する関係値が同期しない。

全キャラクターへ共通の好感度別セリフを追加すると、system promptで定義した個性を潰す。一方、モデルへ差分を決めさせると再現性、Undo、二重処理耐性を失う。

## Decision

- 事実分類と安全上限は共通Policy、重みと表現は版付きRelationship Styleに分離する。
- 会話モデルと独立したloopback抽出モデルを使い、検証済みの現在発言を応答Contextへ含める。
- 新規関係イベントはApplicationが解決した差分を保存し、モデルに数値を決めさせない。
- 低重大度の安全な肯定系だけを自動反映し、重大な低下は確認待ちにする。
- 信頼済みLANへは接続単位の明示許可がある場合だけ、固定許可フィールドの匿名Behavior Envelopeを送る。
- UIはチップ直下の「今回の受け止め」と既存の局所パルスを採用する。

## Consequences

- 同じ出来事でもキャラクターごとの表現と許可範囲内の重みを変えられる。
- 応答前の端末内抽出ぶん、応答開始が遅くなる可能性がある。
- CharacterVersionとRelationshipEventに互換migrationが必要になる。
- LAN同期は既定OFFであり、許可しない接続では関係は画面表示だけになる。

## Rejected alternatives

- 共通の好感度別セリフ: 個性を潰す。
- 会話モデルが数値を直接出力: 再現性と安全境界を失う。
- Relationship Context全体のLAN送信: Profile・出典・履歴を漏らす。
- 会話タイムラインの変化カード: 数値目的化と履歴密度を増やす。

## Review conditions

- 数値目的の会話が代表20シナリオ中20%を超える。
- 応答開始P95が2秒以上悪化する。
- 4キャラクター固定試験で表現差を確認できない。
- LAN Envelopeへ禁止フィールドが1件でも混入する。
