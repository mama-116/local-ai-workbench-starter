# ADR-0016: 承認付きファイル整理と登録済みPowerShellを段階導入する

- Status: Accepted
- Date: 2026-07-17
- Decision owner: 利用者

## Context

Phase 7Aは、永続的変更を残さないメモ帳操作でWindows操作の承認、対象再検査、停止、監査を検証する。一方、利用者が実際に任せたいPC作業には、ファイル整理とPowerShell実行が含まれる。これらは作業効率を大きく高めるが、誤った移動・上書き・削除によるデータ消失、リンク経由の許可逸脱、コマンド展開・子プロセス・権限昇格による影響拡大があり、メモ帳操作と同時に解禁できない。

承認画面を置くだけでは安全境界にならない。利用者が表示された長いコマンドのすべての展開結果を毎回検証することは難しく、モデルが自由形式のPowerShellを生成できれば、固定Policyを迂回する余地が残る。

## Decision

Phase 7Aの10回連続受入後に、Phase 7Bを独立して実装する。

Phase 7Bのファイル操作は、明示許可したフォルダー配下の作成、コピー、名前変更、移動、ゴミ箱またはアプリ管理退避に限定する。入力元と出力先をリンク解決後にも再検査し、上書きと恒久削除を禁止する。変更前に復元ジャーナルを保存し、Undo可能性を確認できない計画は実行しない。

PowerShellは、アプリ側に固定登録したレシピIDと型付き引数だけを受け付ける。レシピはアプリ同梱で書込み不能な、バージョンとSHA-256を固定した `.ps1` とし、`powershell.exe -File` の引数ベクターとPowerShellのパラメーター束縛で呼び出す。引数のコマンド文字列への連結、`-Command`、`Invoke-Expression`、dot source、実行時のスクリプト生成を禁止する。作業ディレクトリ、許可子プロセス、タイムアウト、出力上限、期待終了コードをPolicyで検査し、`-EncodedCommand`、権限昇格、公開ネットワーク通信、秘密情報候補、再帰的恒久削除、未登録プロセス起動を拒否する。

両操作は常に `PLAN_APPROVAL_REQUIRED` とし、実行前に対象、操作順、変更内容、展開済みコマンド、予算、復元方法を表示する。承認は計画JSONとレシピ定義のSHA-256へ束縛し、変更時に失効する。Coordinatorは逐次実行し、停止時は未実行操作を開始せず、PowerShellは今回起動したprocess treeだけを終了する。

任意PowerShellは対象外かつ `DENY` とする。Phase 7Bが20回連続成功し、恒久消失、復元失敗、許可外アクセスが0件であり、登録レシピでは解決できない反復需要が確認された場合にだけ、隔離方式を含む別ADRを作成して再検討する。

## Alternatives considered

| 案 | 評価 |
|---|---|
| PC操作をメモ帳で止める | 最も安全だが、利用者が必要とするファイル整理とPowerShellの実用性を検証できない |
| 任意PowerShellを毎回承認する | 柔軟だが、文字列展開、環境、子プロセス、引用ミスまで人が毎回検証する前提になり、安全境界をPolicyで強制できないため不採用 |
| ファイル操作専用APIと登録済みレシピを使う | 対象と副作用を構造化して拒否試験を作れ、監査・復元・停止を強制できるため採用 |
| 最初からWindows Sandboxで任意コマンドを実行する | ホストへの影響は減らせるが、許可ファイルの受け渡し、結果反映、依存、UXが増えるため、具体的需要が出た後の比較対象とする |

## Consequences

- 臨時のPowerShell作業には新しいレシピ登録が必要で、自由形式実行より遅い。
- ファイル操作とコマンド実行をUI操作Providerへ混在させず、それぞれ契約と拒否試験を持てる。
- 計画承認、監査、停止は既存のComputer Use基盤を再利用できる。
- Undoは無条件の巻き戻しではなく、後続変更を検知した場合に停止して利用者へ判断を戻す。
- 20回の受入は安全の証明ではないが、任意実行を検討する最低条件として事故と復元能力を可視化する。

## Acceptance criteria

- 許可外パス、取消済み許可、リンク・junction・reparse point経由、上書き、恒久削除を実行前と直前再検査で拒否する。
- 復元ジャーナルを操作前に保存し、正常な移動・名前変更・退避をUndoできる。後続変更があれば無断で上書き・削除しない。
- 未登録レシピ、壊れた引数、承認後の定義変更、引数の命令注入、`-Command`、昇格、外部通信、秘密情報候補、未登録子プロセスを拒否する。
- タイムアウト、出力上限、停止操作で今回のprocess treeだけを終了し、通常チャットと別プロセスを壊さない。
- 実行状態、入力、結果サイズ、SHA-256、開始・終了、終了コード、失敗・拒否理由、復元情報をSQLiteへ追記監査する。
- ファイル本文、秘密情報、PowerShell出力全文、個人の絶対パスを通常ログと監査一覧へ露出しない。
- 専用データで異常系を含む20回連続受入を行い、恒久消失、復元失敗、許可外アクセスが0件である。

## Review condition

Phase 7Bの20回連続受入後、または登録レシピの不足で同種の作業が3回以上中断した時点で見直す。任意PowerShellへ進む場合は、このADRを黙って拡張せず、隔離、承認表示、環境変数、署名、ネットワーク、秘密情報、process tree、復元不能操作を扱う別ADRを利用者が承認する。
