# ADR-0007: 会話モデルにQwen 3.5 9Bを使う

- Status: Accepted
- Date: 2026-07-16
- Decision owner: 利用者

## Context

`qwen2.5:7b` は「中国語と英語を混ぜ、理由付きでおすすめする」という依頼に対し、依頼文を言い換えて質問を返し、会話が成立しなかった。PC内の候補を同一条件で比較した。

- `llama3.1:latest`: 5.5秒だが言語指定を守らず、実在が怪しい固有名詞を生成した。
- `gemma2:9b`: 初回31.3秒。おすすめは出したが中国語指定を守らず、一部説明が不正確だった。
- `qwen2.5-coder:14b`: 初回50.2秒。おすすめを返さず、キャラメルをバニラへ変えた。
- `gpt-oss:20b`: 指示を満たしたが初回166.8秒で、翻訳モデルとの切替も重い。
- `qwen3.5:9b`: 初回12.3秒、読込後3.8秒。おすすめと理由を直接返し、GPU使用量は約7.3GiBだった。

## Decision

会話の既定モデルを `qwen3.5:9b` に変更する。

- 文脈長は4096、temperatureは0.3とする。
- 思考モードは使わない。試験では36.8秒後も思考だけで本文を返さなかった。
- 既定キャラクターは、ユーザーの明示指定を優先し、質問へ直接答え、未確認の固有名詞を作らないよう指示する。
- 翻訳はADR-0006どおり `llama3.1:latest` を使い、文脈長を4096へ制限してGPU内での共存を優先する。
- 既存会話の履歴と旧キャラクター版は残し、選択先だけ新モデル・新版へ変更する。

## Known limitation

同じ試験で、おすすめと理由は返したものの、中国語と英語の両方を使う指定は完全には守れなかった。また、9Bモデルでは固有名詞の誤生成を完全に防げない。複雑な形式指定を確実に検査・再実行する処理は、高度なルーティング段階で扱う。

## Alternatives

- `gpt-oss:20b` を既定にする: 品質は高いが待ち時間が長すぎるため不採用。
- `qwen3.5:4b` を取得する: 軽量だが、今回の問題に対して9Bより精度を下げる理由がないため不採用。
- 外部APIを使う: 外部送信と費用経路を生むため不採用。

## Review condition

質問への直接回答が継続的に失敗する場合、または複雑な言語・形式指定が主要用途になった場合、完全無料・ローカル実行を維持した上でモデルまたは応答検査方式を再比較する。
