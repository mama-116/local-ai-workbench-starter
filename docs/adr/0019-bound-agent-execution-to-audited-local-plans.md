# ADR-0019: Agent実行を監査可能なローカル計画へ制限する

- Status: Accepted
- Date: 2026-07-17
- Decision owner: 開発者

## Context

Phase 6までの実行は、利用者の1回の要求またはアプリに固定登録した定期ハンドラーで終わる。Phase 7ではモデルが複数の手順を提案できるが、手数、時間、許可ツール、送信先をモデル自身に決めさせると、停止不能、許可の拡張、PRIVATEデータの外部送信につながる。自律書込みや実OS入力は一方向ドアであり、この共通基盤と同時に有効化できない。

## Decision

- 1 runの既定上限を、総予算5単位、最大5手、最大60秒、同時1件とする。各ツールの予算単位はアプリ同梱の固定定義だけが宣言し、モデルは変更できない。
- run開始時に許可ツール名を固定し、アプリ側レジストリとの積集合だけを実行する。計画途中の追加・定義変更は新しいrunと承認を必要とする。
- 次手を生成するSourceは同一PC上の `local` かつ `no_charge` に固定し、会話、目的、直前のPRIVATE結果をLAN・外部・有料Sourceへ渡さない。
- PRIVATEデータをPC外へ送る操作は、承認があっても拒否する。送信先が不明なツールも拒否する。
- 外部投稿と外部削除は、会話、目的、ツール定義、データ区分、上限、許可リストを含む正規化済み1操作のハッシュへ束縛した一回限り・30秒有効の承認を毎回要求する。同じ承認の再利用、別操作・別会話への流用、計画変更後、期限切れの利用を拒否する。課金は `strict_free` のため承認があっても拒否し、将来別成果物で許可する場合にも毎回承認を要求する。
- Phase 7の最初のProviderはOSへ接続しないFakeだけとする。本物のローカル書込み、実OS入力、外部操作ProviderはそれぞれのIssueと一方向ドア承認まで登録しない。
- runとstepはSQLiteへ追記監査する。完了済みの可逆操作より後で失敗または停止した場合、復元トークンを持つ操作を逆順に復元し、復元結果も監査する。復元不能操作はこの段階で許可しない。
- 起動時に残った `running` run/stepは `failed` へ復旧し、自動再開しない。

状態値とデータ区分は [ARCHITECTURE.md](../ARCHITECTURE.md) を正本とする。

## Alternatives

| 案 | 判定 | 理由 |
|---|---|---|
| Phase 6の単発実行のまま何もしない | 却下 | 複数手の停止・監査・承認失効を検証できず、#19と#21で共通境界を再実装することになる |
| ToolCoordinatorの3回上限だけを再利用する | 却下 | 発言単位の読取り上限であり、経過時間、作用種別、操作ごとの承認、復元を表現できない |
| 最初からComputer Useとファイル書込みを実装する | 却下 | Provider固有の危険と共通Coordinatorの欠陥を切り分けられず、一方向ドアを同時に通る |
| 固定計画、固定上限、Fake Provider、永続監査から始める | 採用 | OSや外部へ作用せず、拒否・停止・承認・復元を決定論的に検証できる |

採用案への最も強い反論は、5手・60秒では実用的なAgent作業に短すぎることである。しかし初回の目的は長時間自律実行ではなく、安全境界を破れないことの実証である。上限到達率と正常完了時間を監査できるため、実測後に値だけを見直せる。

## Consequences

- モデルの出力は提案であり、許可、予算、承認、データ境界の正本にならない。
- 外部投稿等は計画全体の一括承認ではなく、作用する操作ごとに利用者確認が必要になる。課金は初版では確認画面へ進まず拒否する。
- Fake Provider段階では実用的なOS操作や書込みは行えないが、後続Providerが同じ停止・監査・復元契約を再利用できる。
- 監査DBにはPRIVATEな引数本文を保存できるが、通常ログと監査一覧にはハッシュ、サイズ、状態、失敗理由だけを返す。

## Acceptance criteria

- 6手目、6予算単位目、60秒超過の各境界で、Providerを呼ぶ前に停止する。
- runの許可リスト外、レジストリ外、送信先不明、PRIVATEのPC外送信を `denied` として監査する。
- Agent Sourceが `local + no_charge` 以外なら、目的や直前結果を渡す前にrunを `denied` として監査する。
- 外部投稿と外部削除は、承認なし、ハッシュ不一致、再利用のいずれもProviderを呼ばない。課金と `no_charge` 以外のProviderは承認があっても呼ばない。
- 30秒を超えた承認、未来時刻、timezoneなし、別会話・別目的の承認を拒否する。
- 途中失敗時にFakeの可逆操作を逆順に復元し、`restored` または `restore_failed` をstep監査へ残す。
- 再起動後に未完了runを `failed` へ復旧し、自動再開しない。

## Review condition

#19のFake Provider試験へ接続するときに、上限値、承認ハッシュ、停止時間、監査スキーマを再確認する。復元失敗、許可外実行、PRIVATE外部送信が1件でも発生した場合は、実Providerを登録せず共通Coordinatorを修正する。
