# ADR-0006: 複数のプライベートLAN内Ollamaへ会話単位で接続する

- Status: Accepted
- Date: 2026-07-16
- Decision owner: 利用者

## Context

このPC以外に、同じローカルネットワークの `192.168.1.17` でもOllamaが稼働している。接続先を全体設定だけで切り替えると、同名モデルが複数端末にある場合や過去の会話を再開する場合に、どの端末を使ったか判別できない。一方、任意URLを許可すると外部送信と費用経路を生み、`strict_free` の条件を弱める。

## Decision

- このPCとプライベートLAN内の複数Ollama接続先を登録できるようにする。
- 初期候補として `http://127.0.0.1:11434` と `http://192.168.1.17:11434` を表示する。
- 接続先とモデルは会話単位のモデル設定へ保存し、送信時に保存済み接続先へ振り分ける。
- 許可する接続先はHTTPのループバックまたはRFC 1918プライベートIPv4に限定する。
- 公開IP、ホスト名、HTTPS、URL内認証情報、パス、クエリは拒否する。
- LAN端末のモデル一覧は読取専用で確認できるが、会話送信には相手端末でOllama Cloudを無効化した確認を必須とする。
- Cloud名を含むモデル、実体サイズや形式を確認できないモデルは従来どおり拒否する。
- 日本語翻訳はこのPCのOllamaと `llama3.1:latest` を引き続き使い、LAN側の会話モデルと分離する。
- 接続先の物理削除は初版では実装せず、追加と編集だけを提供する。

## Alternatives

- アプリ全体で接続先を1つだけ切り替える: 実装は簡単だが、会話の再現性がなくなるため不採用。
- LAN内IPなら確認なしで送信する: 操作は少ないが、相手OllamaのCloud転送を防げないため不採用。
- 任意URLとAPIキーを許可する: クラウドへ拡張しやすいが、完全無料・ローカル運営の境界を破るため不採用。

## Consequences

- 複数PCのGPUとモデルを同じ画面から選べる。
- LAN端末が停止していても、他の接続先は継続利用できる。
- LAN端末ごとにCloud無効化を利用者が確認する手順が必要になる。
- 接続先名をモデル実行ログへ残すため、過去の実行先を追跡できる。

## Review condition

LAN内のOllamaを自動発見する必要が出た場合、無断スキャンを避ける確認手順と探索範囲を別ADRで定義する。TLS、認証、VPN、公開ネットワーク接続が必要になった場合は、本ADRの許可範囲を広げず、別の安全・費用モードとして検討する。
