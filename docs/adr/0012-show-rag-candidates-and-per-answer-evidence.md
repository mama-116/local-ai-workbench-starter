# ADR-0012: RAGの参照候補と回答に使った根拠を区別する

- Status: Accepted
- Date: 2026-07-17
- Decision owner: 利用者

## Context

入力欄の上に表示する「参照中」は、資料が回答へ渡されたように見える。しかし初期RAGは、会話に選択した資料を検索対象にするだけで、質問と一致するチャンクがなければ資料をプロンプトへ渡さない。この差が画面から判別できず、利用者が資料の影響を確認できない。

## Decision

- 入力欄の資料表示は「参照候補」とし、回答へ必ず使われるという意味を持たせない。
- 資料を選択した状態で実行したrunには、選択資料数を保存する。検索結果が0件でも保存する。
- AI回答ごとに次を表示する。
  - 一致するチャンクをプロンプトへ渡した場合: 「資料使用あり」と件数。
  - 資料を検索したが一致しなかった場合: 「該当箇所なし」。
  - 資料を選択せず実行した場合: RAG状態を表示しない。
- 「資料使用あり」では、文書名、原文位置、実際にプロンプトへ渡したチャンク本文を折りたたみ表示する。
- 表示判定は現在の選択状態から推測せず、runに保存した当時の記録を正本とする。
- 既存runには当時の選択状態を安全に復元できないため、RAG状態を表示しない。

## Alternatives

- 選択中の資料があれば過去回答にも「該当箇所なし」を表示する: 実行当時の状態と異なる可能性があるため不採用。
- 短い資料を毎回全文注入する: 影響は明確だが、質問と無関係な資料が回答やキャラクター性を変えるため不採用。
- 資料あり・なしの回答を常に並べる: 検証には強いが、生成時間と画面占有が倍増するため初期UXでは不採用。

## Consequences

- 資料が選ばれている状態と、回答に実際に使われた状態を区別できる。
- 一致しない検索を利用者が把握でき、検索方式の改善判断に使える。
- runごとのRAG利用記録と、引用チャンク本文の読み出しが必要になる。
- 根拠表示により回答カードが長くなり得るため、本文は初期状態で折りたたむ。

## Review condition

根拠表示がほとんど開かれず画面の情報量だけが増える場合は、状態ラベルのみへ簡略化する。日本語の言い換えで「該当箇所なし」が頻発する場合は、表示契約を維持したまま検索方式を見直す。
