# ADR-0011: CONTROL DESKから起動確認付きで再起動する

- Status: Accepted
- Date: 2026-07-17
- Decision owner: 利用者

## Context

開発中の機能反映や一時的な接続復旧で再起動が必要になるが、ターミナル操作やプロセス探索は日常利用の負担になる。単に旧プロセスを終了してから新プロセスを起動すると、起動失敗時にアプリが閉じたままになる。

## Decision

- A案を採用し、右側 `CONTROL DESK` に「アプリを再起動」ボタンを置く。
- `Ctrl+Shift+R` を同じ操作へ割り当てる。
- 生成中は再起動操作を無効化する。
- 旧プロセスは新プロセスを起動し、新プロセスが固定ローカル保存先へreadyファイルを書いたことを確認してからウィンドウを閉じる。
- ready確認がタイムアウトまたは新プロセスが異常終了した場合、旧プロセスを残して利用者へ失敗を表示する。
- readyファイルは `app/.local-data/restart` 内だけに作成し、会話本文や秘密情報を含めない。
- 開発起動では現在のPython実行ファイル、引数、作業ディレクトリを再利用する。
- Windows配布版ではホストEXEを引数なしで起動する。親プロセス専用の `FLET_DART_BRIDGE_PORT` と `FLET_DART_BRIDGE_EXIT_PORT` は子へ渡さず、保存先など他の環境変数は維持する。

## Alternatives

- B案、画面上部の再起動アイコン: 押しやすいが日常操作で誤操作しやすいため不採用。
- C案、保守メニュー内: 管理機能をまとめやすいが再起動までの操作が増えるため不採用。
- 旧プロセスを先に閉じる: 実装は短いが起動失敗から復帰できないため不採用。

## Consequences

- 日常利用者がターミナルを開かず再起動できる。
- 新旧プロセスがready確認まで短時間だけ同時に存在する。
- アプリ自体が起動不能な場合はボタンを利用できない。

## Review condition

開発版または配布版で新プロセスの起動確認が安定しない場合、外部ランチャーを正本に切り替える。二重起動やDB競合が再現した場合は単一インスタンス制御を追加する。
